# Yummi v1.1.1b

Sandbox browser automation, cited web research, and a smoother operator workspace.
This is a beta release, not a guarantee of autonomous model correctness.

> **Historical release snapshot:** Verification counts and model results below apply to the recorded release run. See the [maintained documentation](../README.md) for this checkout.

## Highlights

- Nine Chromium tools cover navigation, DOM snapshots, interaction, JavaScript,
  screenshots, tabs, storage, logs and session lifecycle. Headless and graphical
  modes execute inside the Kali sandbox; no host browser is launched by these tools.
- `web_search` and `web_fetch` provide cited public-web evidence, domain filters,
  original-source reading, literal finding and pagination. Research credentials,
  DNS, HTTP and content parsing stay inside the gateway-routed sandbox.
- Operator approvals, gateway permissions and additional-step controls remain
  accessible above the composer. Conversations update without reloading the page.
- Trace cards have consistent heights, independently scrollable content,
  keyboard access and visible loading/error states. Bash retains its shared
  operator shell and cleans up only the disconnected client's attachment.
- Runner-owned execution history rejects fabricated execution fields in model
  plans. This structural boundary does not judge the truth of free-form summaries.

## Reliability and security

- Fixed browser proxy response handling and long-lived response streaming.
- Preserved browser sessions across persistent Docker MCP transport calls.
- Sandbox-MCP tests now run in networkless Kali Docker as UID 1000, without
  host mounts or runtime confinement bypasses. UI Docker validation includes lint.
- MCP discovery exposes 58 tools. Gateway policy remains fail-closed and
  operator-controlled; this release does not automatically enable external access.

## Verification scope and known limitations

CI covers Go tests/lint/vulnerability checks, Rust tests/lint/audit, UI lint,
103 UI tests, production build and real isolated sandbox-MCP tools including
Chromium and tmux. Live provider/model QC is separate from the isolated CI suite.

Direct browser and research checks passed. MiniMax/OpenRouter passed the cited
research, multi-source comparison and headless-form scenarios. The recorded
full-browser autonomous scenario failed because its final summary claimed a
form result absent from the actual observations. Model-generated conclusions
still require evidence review; tool success is not proof of task completion.
See [detailed QC evidence](../agent/web-research-qc.md).

Fetch supports public HTTPS text/HTML, not PDF extraction or arbitrary private
targets. CAPTCHA/login flows and model reliability are not guaranteed. Existing
test-environment warnings and the Vite bundle-size warning remain non-blocking.

## Upgrade

Check out `v1.1.1b`, retain your private configuration, then run `make start BUILD=1` to
rebuild and start the stack with the configured provider/model. Plain `make start` reuses existing images. Do not substitute
bare `docker compose up` when relying on values exported by `.yummi.conf`.
Gateway restarts reset egress to `block_all`; authorize access explicitly in
GATEWAY when needed. No credentials belong in release notes or tool arguments.
