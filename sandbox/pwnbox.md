## Tool gotchas (verified on this image)
- `curl` normalizes dot segments, including percent-encoded ones (`%2e`, `%2e%2e`).
  A path such as `/cgi-bin/.%2e/...` is silently rewritten before it is sent, so the
  server never sees what you meant. For raw-path tests, use `curl --path-as-is`
  and confirm with `-w '%{url_effective}'`, or send the request with `printf | nc`.
- `printf` consumes `%` as a format character. Write `%%` to send a literal `%`
  (`printf 'a%%2e'` sends `a%2e`), and check what was actually sent.
- A `403` with the server logging "denied by server configuration" means the
  request reached the target, and authorization blocked it. It is not a
  path-normalization failure. Read the server's error log before you change the payload.
- A `404` on a path you expected to be mapped usually means your client changed the
  path or the route does not exist. Check the URL the client actually sent first.

## Network reality
- All outbound traffic from this box goes through the gateway (default route
  `172.20.0.2`). The gateway decides what is reachable; the operator can change its
  egress mode.
- `GATEWAY_BLOCKED` or `COMMAND_BLOCKED` in a result means **policy refused the target**.
  It does not mean the host is down.
- A bare timeout or "no route" can mean either a blocked path or a dead host. Test with
  a second, different tool before concluding the target is down.

## Long-running work
- `run_command` returns only when the process exits (hard cap 10 min). Anything that
  waits for a connection, such as a listener, a shell handler, or `http.server`, will
  hit that cap.
- If the persistent terminal tools (`term_open`, `term_run`, `term_read`, `term_wait`,
  `term_keys`, `term_close`) are in your toolset, run listeners and servers there.
  Use `term_wait` with a pattern to know when something is ready.
